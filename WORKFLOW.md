# AI Workflow Comparison

## Feature
React Settings Form with validation and responsive design.

## Round One – Vague Prompt

For the first attempt, I used a very short prompt: "Create a React settings form." The AI generated a working solution with basic functionality, but several important details were left to interpretation. Although the form worked, it required more manual review to verify validation, accessibility, responsiveness, and overall code organization. The AI did not clearly explain how requirements were satisfied, so I had to inspect the code myself.

## Round Two – Detailed Prompt

For the second attempt, I provided a detailed prompt describing the required sections, validation rules, reusable components, accessibility requirements, responsive layout, and verification steps. The AI produced a much better organized project with reusable components, validation logic, cleaner file structure, and better accessibility. It also explained its implementation and provided verification steps.

## Comparison

The second workflow produced higher quality code with less manual correction. The code was easier to understand because the requirements were clearly specified. Reusable components improved maintainability, validation was more complete, and accessibility considerations were included from the beginning.

## AI Mistake I Caught

During the first round, the AI did not explicitly verify that every requirement was satisfied. I manually reviewed the generated project before accepting it. This showed me that AI-generated code should always be verified instead of being accepted without review.

## What I Learned

This exercise taught me that the quality of AI output depends heavily on the quality of the prompt. A precise prompt with clear requirements, constraints, and verification steps results in better code and reduces review time. Going forward, I will always provide detailed requirements and verify the generated code before using it.
